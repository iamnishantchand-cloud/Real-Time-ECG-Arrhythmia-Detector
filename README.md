# Real-Time ECG Arrhythmia Detector

AI-powered heartbeat classification system that analyzes ECG (electrocardiogram)
signals and automatically flags abnormal heart rhythms (arrhythmias) using a
1D Convolutional Neural Network trained on real hospital recordings.

> ⚠️ **Research Prototype** — This is a hackathon demonstration project. It is NOT
> a validated medical device and must not be used for clinical diagnosis or treatment
> decisions. See [Limitations](#limitations) below.

## The Problem

Cardiac arrhythmias — abnormal heart rhythms — affect millions of people worldwide
and can be life-threatening if not detected early. Cardiologists identify arrhythmias
by visually inspecting ECG waveforms, but this requires expertise and is
time-consuming. An AI assistant that can automatically flag suspicious beats could
help clinicians prioritize their attention, especially in high-volume monitoring
settings like ICUs.

## How It Works

### Pipeline Overview

```
MIT-BIH Database → Data Prep → 1D-CNN Training → Evaluation → Live Dashboard
   (PhysioNet)     (segment     (classify         (validate    (real-time
                    & normalize   each beat)        accuracy)    playback)
                    beats)
```

### 1. Data Loading & Segmentation (`data_prep.py`)

Loads ECG recordings from the MIT-BIH Arrhythmia Database via PhysioNet — real
30-minute, 2-lead ECG recordings from 48 patients at Beth Israel Hospital,
annotated beat-by-beat by cardiologists. Each heartbeat is extracted as a
250-sample window centered on the R-peak (the tallest spike), capturing the full
PQRST complex. Beats are normalized to [0,1] and split by **patient** (not
randomly) to prevent data leakage.

### 2. Model Training (`train_model.py`)

A 1D Convolutional Neural Network with 3 conv layers (32→64→128 filters) learns
to classify beats into 5 AAMI classes: Normal (N), Supraventricular ectopic (S),
Ventricular ectopic/PVC (V), Fusion (F), and Unknown (Q). Class weights handle
the heavy imbalance (~80% Normal beats). BatchNormalization and Dropout prevent
overfitting.

### 3. Evaluation

Before building the dashboard, the model is evaluated on held-out test patients.
Key metrics: overall accuracy, per-class precision/recall/F1 (especially **recall
on abnormal classes** — missing a real arrhythmia is the dangerous failure mode),
and a confusion matrix. All metrics are saved for dashboard display.

### 4. Live Dashboard (`app.py`)

A Streamlit app simulates real-time ECG monitoring by replaying pre-recorded
test signals. The ECG waveform scrolls left-to-right like a bedside monitor,
and each heartbeat is classified by the CNN as it appears. Abnormal beats are
highlighted in red/orange with confidence scores. Includes a beat comparison
view showing how a flagged beat differs from a normal one.

## Quick Start

### Prerequisites

- Python 3.10+
- pip

### Installation & Run

```bash
# Clone / download this project
cd ecg-arrhythmia-detector

# Install dependencies
pip install -r requirements.txt

# Step 1: Prepare data (downloads from PhysioNet, ~2-5 min)
python data_prep.py

# Step 2: Train model & evaluate (~3-10 min depending on hardware)
python train_model.py

# Step 3: Launch dashboard
streamlit run app.py
```

The dashboard will open at `http://localhost:8501`.

### Demo Walkthrough

1. **Live Monitor tab**: Select "Patient 207" or "Patient 208" (both have
   frequent PVCs). Click ▶️ Play and watch the AI flag abnormal beats in
   real time.
2. **Patient 100**: A mostly-normal recording for contrast — few or no alerts.
3. **Model Performance tab**: Shows the evaluation metrics and confusion matrix
   to demonstrate validation rigor.
4. **Beat Comparison**: When an abnormal beat is flagged, scroll down to see
   it overlaid with a normal beat — the visual difference is immediately
   apparent (wider QRS, different amplitude pattern).

## Model Architecture

```
Input: (250, 1) — one heartbeat, one ECG lead

Conv1D(32, kernel=7) + BatchNorm + ReLU + MaxPool(2)    → (125, 32)
Conv1D(64, kernel=5) + BatchNorm + ReLU + MaxPool(2)    → (62, 64)
Conv1D(128, kernel=3) + BatchNorm + ReLU + MaxPool(2)   → (31, 128)
GlobalAveragePooling1D                                   → (128,)
Dense(128, ReLU) + Dropout(0.5)                          → (128,)
Dense(64, ReLU) + Dropout(0.3)                           → (64,)
Dense(5, Softmax)                                        → (5,)

Output: probability distribution over 5 AAMI classes
```

## Dataset

**MIT-BIH Arrhythmia Database** (PhysioNet)
- 48 half-hour ECG recordings from 47 patients
- Recorded at Beth Israel Hospital, Boston (1975-1979)
- 2 leads, sampled at 360 Hz
- ~110,000 beats total, annotated by two cardiologists
- Beat types grouped into 5 AAMI classes (N, S, V, F, Q)

## AAMI Beat Classes

| Class | Name | Description | Clinical Significance |
|-------|------|-------------|----------------------|
| **N** | Normal | Normal sinus beat | Healthy rhythm |
| **S** | Supraventricular | Atrial premature beat | May indicate AFib risk |
| **V** | Ventricular | Premature ventricular contraction (PVC) | May indicate VT risk |
| **F** | Fusion | Normal + ventricular hybrid | Transitional beat |
| **Q** | Unknown | Paced or unclassifiable | Requires review |

## Limitations

> **This system has NOT been clinically validated and must NOT be used for
> medical diagnosis or treatment decisions.**

1. **Retrospective data only** — Validated solely on the MIT-BIH Arrhythmia
   Database (recorded 1975–1979). Has not been tested on real-time data from
   modern ECG devices or wearables.

2. **Limited demographics** — MIT-BIH contains 48 patients from a single US
   hospital. Performance may not generalize across diverse populations, ages,
   body types, or comorbidities.

3. **Simplified classification** — Groups beats into only 5 classes. Real
   clinical ECG interpretation involves dozens of rhythm patterns, 12-lead
   morphology analysis, and integration with clinical context (symptoms,
   history, medications, labs).

4. **No regulatory clearance** — Would require FDA 510(k) or De Novo
   classification (US), CE marking under EU MDR (Europe), or equivalent
   regulatory approval before any clinical deployment.

5. **Single-lead analysis** — Uses only Modified Limb Lead II. Clinical
   ECG interpretation uses standard 12-lead configurations.

6. **Not real-time validated** — The "live" playback is a simulation replaying
   recorded data, not processing from an actual ECG sensor in real time.

## Real-World Impact

If fully developed, validated, and regulatory-cleared, a system like this could:

- **Assist overworked clinicians** by pre-screening continuous ECG monitors
  and flagging only the beats that need human review
- **Reduce alarm fatigue** in ICUs by improving the specificity of cardiac
  alarms (currently ~85-90% of ICU alarms are false)
- **Enable remote cardiac monitoring** by automating first-pass analysis of
  home/wearable ECG recordings
- **Accelerate triage** in emergency departments by prioritizing patients
  with detected arrhythmias

**Path to clinical deployment would require:**
1. Prospective clinical trials at multiple hospitals
2. Validation across diverse patient populations
3. Integration with existing hospital EHR/monitoring systems
4. Regulatory submission and clearance
5. Clinician training and workflow integration
6. Continuous post-market surveillance
